# PROPKA 固定 λ=0.5 的还原态案例对照

按用户要求固定 λ=0.5，参考 pKa=8.0，pH=7.5；没有扫描 λ、训练新模型或选择有利构象。使用 PROPKA 3.5.1，对既有 120 个结构逐帧计算（100 个生产、10 个最小化、10 个平衡），原模型及评分保留。

修正公式：`sigmoid(logit(original_score) - 0.5*(pKa-8.0))`。硫醇盐分数另按 `1/(1+10**(pKa-7.5))` 计算。pH 不显式进入朋友提出的修正评分公式。先逐帧转换，再汇总；没有先平均概率或 pKa 再做非线性转换。

## 端基适配与警告

直接输入原 PDB 时，PROPKA 将 ALA1 错识别为 N+，并将 NHE15 识别为可滴定 N31 胺。本工具仅在内存/输入副本中将 ACE 改为 ATOM 记录，保持全部坐标不变；在组提取前明确将连接 Cys14 羰基的一级酰胺 N 指定为 N.am，采用内置中性 NAM 参数。没有更改 PROPKA 的 pKa 经验参数。
逐帧断言核验：ACE 羰基与 ALA1 相连、无自由 N+/C-、NHE 是中性不可滴定 NAM 且有两个氢、两个 Cys 未被识别为二硫键。原 PDB、权重及原分数哈希核验通过。
PROPKA 的 NAM 检查模板按二级酰胺预期 N+1H，而当前一级酰胺为 N+2H，因此每帧产生一次原子数量警告；全部 120 条保存在 propka.log。检查源码确认全部三个相互作用原子仍被保留；没有删除真实氢来消除警告。该参数向一级酰胺的适用性仍是近似，结果不能称为未经适配的标准 PROPKA 命令行结果。
inputs 中只保存 ACE 记录转换后的几何输入；单独对这些 PDB 运行 propka3 仍缺少 NHE 类型适配，必须使用下面的正式脚本。typing_audit.json 保存实际计算采用的各基团类型、电荷、键连与 pKa。

## 复现

```powershell
python -m pip install -r requirements.txt
python tools/score_propka_case.py --output results/propka_replay
```

λ、参考 pKa 和 pH 固定在脚本中，无调 λ 命令参数。默认读取已交付原评分，不重训；输出目录必须不存在。results.csv 包含全部 240 个位点，筛选 stage=production 得到 200 行正式比较。

## 局限

这是未校准的经验修正，不是效率预测或恒 pH 模拟。100 个生产快照时间相关，来自有限的中性巯基采样；预测 pKa 的均值不是平衡有效 pKa。相关训练片段与测试肽重叠，不能据此验证独立泛化。未显式模拟 TFA/反应缓冲液。固定 λ 下得不到预期排序已如实保留。

PROPKA 官方文档：https://propka.readthedocs.io/；Python 接口与基团源码：https://github.com/jensengroup/propka/tree/v3.5.1/propka 。
